# AI 协作指南（学生用）

> 本课程鼓励你用 AI 学习和开发，但有一条底线：**AI 是陪练，不是枪手**。
> 你要能解释自己提交的每一行代码；跑不通时，要能用课程命令自己定位。

## 一、什么时候用 AI

| 场景 | 适合问 AI | 不适合 |
|---|---|---|
| 看不懂报错 | ✅ 贴**完整报错原文**+上下文 | ❌ 只说"跑不起来" |
| 理解概念 | ✅ 让它用本课程的例子解释 | ❌ 让它代替你读代码 |
| 写任务节点 | ✅ 让它给思路/片段，**你逐行看懂并改** | ❌ 整段复制交作业 |
| 调参 | ✅ 问"这个参数调大会怎样" | ❌ 让它猜数值不验证 |
| 排障 | ✅ 让它列排查顺序，你执行并反馈 | ❌ 没验证就相信结论 |

## 二、怎么问：复制这段上下文

本课程环境与社区常见教程不同（**锁版本 + 17 个补丁**），直接问通用问题会得到不适用的答案。每次提问请附上下面这段：

```text
【课程环境上下文】
- 飞控：PX4 v1.15.4（SITL，源码在 PX4-Autopilot/）
- ROS2：Humble；仿真器：Gazebo Harmonic（不是 Classic，也不是 Ignition Fortress）
- 平台：XTDrone2（锁定 commit）
- 通信：PX4 <-> MicroXRCEAgent(UDP 8888) <-> ROS2 节点
- 单机命名空间示例：/x500_0（由机型 gz_x500 推导）
- 统一控制接口：drone_sim.px4_interface.PX4Interface（不要自己 create_publisher 连 PX4）
- 发布端 QoS 必须 BEST_EFFORT + VOLATILE（否则可能死锁）
- 订阅端 QoS：BEST_EFFORT + TRANSIENT_LOCAL
- 坐标系：PX4 用 NED（z 向下为正），Gazebo 用 ENU（z 向上为正）

【提问要求】
1. 先给可直接执行的命令或代码，再解释
2. 不要假设版本；如果不确定，明确说"需确认"
3. 如果我的环境有锁版本/补丁导致的差异，请指出

【我的问题】
（在这里写你的具体问题）
```

## 三、怎么验：AI 常错的五个地方

AI 按通用 PX4/ROS2 知识回答，以下地方最容易与本课程不符，**每次都要核对**：

| 易错点 | AI 可能给的 | 本课程实际 |
|---|---|---|
| **消息字段** | `OffboardControlMode.actuator` | 1.15 版是 `thrust_and_torque` 和 `direct_actuator`（无 `actuator`） |
| **QoS** | 默认 RELIABLE | 发布端必须 BEST_EFFORT+VOLATILE，否则共享内存流控死锁 |
| **命名空间** | `/fmu/...`（相对） | 本课程用绝对 `/x500_0/fmu/...`，多机必须匹配 `target_system`=实例号+1 |
| **坐标系** | 混用 z 符号 | PX4 的 `pos.z` 向下为正；接口 `alt()` 向上为正，别混 |
| **命令与版本** | 社区教程的旧命令 | 本课程锁 v1.15.4，部分参数/命令与新版不同，以仓库代码为准 |

**验证方法**（不要只信 AI 的说法）：

```bash
# 字段名：以本机 px4_msgs 为准
grep -vE "^#|^$" ros2_ws/src/px4_msgs/msg/OffboardControlMode.msg

# 接口实现：以源码为准
grep -nE "QOS_PUB|def heartbeat_position|def request_offboard_and_arm" \
  ros2_ws/src/drone_sim/drone_sim/px4_interface.py

# 跑通才是真：用判分系统证明
python3 tools/grade.py --scenario <场景id> --runs 1
```

## 四、标准流程：先设计 → 问 AI → 你实现 → 验证 → 讲清

1. **先自己想**：这个功能要哪几个话题/参数/状态？写下你的猜想（哪怕不完整）。
2. **问 AI**：带上上下文，让它给方案和代码片段。
3. **你实现**：逐行看懂，自己敲/改，加注释；AI 给的片段要能解释每行为什么。
4. **验证**：跑命令、看日志、跑判分；不通过就带着**实际报错**再问 AI（不是"还是不行"）。
5. **讲清**：向同学或"零基础角色"解释你的改动，对方能照着复现才算过。

## 五、本课程专属：让 AI 修"埋好的刺"

课程在每章任务卡里埋了故障（QoS 不匹配、Agent 缺失、命名空间错、坐标系反了、参数写错等）。正确用法：

1. 先自己观察现象（看日志、看话题、看状态位）；
2. 把你**实际看到的现象**给 AI，让它列排查步骤；
3. 按步骤执行，把每一步的输出反馈给 AI；
4. 修好后记录"现象→原因→验证命令→修复"，这就是你的排障笔记。

> 踩一次比讲十次管用。被 AI 直接告知答案，等于跳过这个练习。

## 六、边界

- 可以用 AI 解释、查思路、给片段、帮排障、优化表达。
- 不可以整段复制未理解的代码当作自己的作业提交。
- 实验报告要写清：哪些是自己想的、AI 给了什么、你改了什么、怎么验证的。
