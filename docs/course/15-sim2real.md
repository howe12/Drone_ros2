# 15 Sim2Real：实机之路

> 难度 L6 · 对应实验 E12（仿真侧完成，实机待硬件）· 进阶阅读章 · 预计 60–90 分钟

## 本章问题

你在仿真里让飞机起飞、避障、精准降落、编队，甚至跑通了判分。把代码拷到真机上，能飞吗？

**大概率不能。** 而且不是"某一行代码要改"，而是**一整套假设会被打破**：

- 仿真里 EKF 完美收敛，实机有 GPS 多路径、磁干扰、机架振动；
- 仿真里电机响应理想，实机有死区、延迟、电池压降；
- 仿真里相机-IMU 外参是理想值，实机必须逐台标定；
- 仿真里"撞了就重来"，实机桨会伤人。

这一章不教你怎么飞真机（本仓库没有真机验证），而是给你一份**迁移前的检查清单和方法**：从仿真到实机，到底差在哪几层。

要解决四件事：

1. 实机前必须确认哪些条件（有脚本可跑）。
2. 差距分布在哪些层，各层以什么症状暴露。
3. 参数整定怎么从仿真值推到实机值。
4. 迁移的正确顺序（为什么不能一步到位）。

## 学习目标

| 维度 | 学习前 | 学习后 |
|---|---|---|
| 迁移认知 | 以为"代码能跑就能飞" | 能列出四层差距并说出各自症状 |
| 前置检查 | 直接上机 | 会用 `sim2real_check.sh` 逐项确认 |
| 外参标定 | 不知道外参是什么 | 理解相机-IMU-机体标定为什么必须实测 |
| 参数整定 | 照抄仿真参数 | 知道用日志回放对比、逐步调整 |
| 安全前置 | 先飞起来再说 | 明白"围栏+急停+监督层"必须先于首飞 |
| 诚实边界 | 把仿真结论当实机结论 | 能明确标注"未在真机验证" |

## 前置知识

需要完成第 11 章（安全监督）、第 6 章（真值验证）、第 8 章（VIO 失败案例）。不要求有真机。

**先跑检查，再谈迁移。** 第 1 节把 9 项前置检查跑一遍——即使没有真机，这一步也能确认"仿真侧是否真的就绪"。

## 1. 实机前，先跑一遍检查

### 1.1 运行前置检查

```bash
bash scripts/sim2real_check.sh
```

三组检查，并生成一份 PX4 参数模板。

**第一组：环境**

| 检查 | 意义 |
|---|---|
| ROS2 Humble 环境 | 基础运行时 |
| PX4 源码目录 | 固件可编译 |
| MicroXRCEAgent | 通信桥可用 |
| `px4_msgs` 已编译 | 消息定义就绪 |
| `drone_sim` 已编译 | 你的节点可用 |

**第二组：代码与文档**

| 检查 | 意义 |
|---|---|
| 安全监督节点 | **实机必须有**（第 11 章） |
| Sim2Real 文档 | 有据可查 |
| 集群智能体 | 多机能力就绪 |
| 行为树任务 | 任务编排就绪 |

**第三组：生成参数模板** → `docs/px4_params_template.txt`。

### 1.2 参数模板里有什么

```text
GF_ACTION        2      # 地理围栏动作 2=返航
GF_MAX_HOR_DIST  100    # 水平围栏 m
GF_MAX_VER_DIST  120    # 垂直围栏 m
COM_RC_LOSS_T    5      # 遥控失联超时 s
NAV_RCL_ACT      2      # 失联动作 2=返航
COM_LOW_BAT_ACT  2      # 低电量动作 2=返航
COM_DISARM_PRFLT 10     # 未解锁自动上锁 s
MPC_XY_VEL_MAX   8.0    # 最大水平速度 m/s
MPC_Z_VEL_MAX_UP 3.0
MPC_Z_VEL_MAX_DN 1.5
EKF2_HGT_MODE    0      # 0=气压 1=GPS 3=视觉
EKF2_GPS_CHECK   21
```

**这些是"仿真对齐值"，上机必须按场地重设。** 比如 100 米围栏在小区里飞明显太大——模板是起点，不是答案。

**为什么先给参数再飞**：这些参数是**保命的**。围栏、失联动作、低电量动作配错，第一次飞就可能飞丢。

### 1.3 模板值 vs PX4 默认值：为什么必须改

第 1.2 节那张模板不是"官方推荐值"，而是"**把危险默认值改安全**"的结果。查 PX4 源码可以确认默认值：

| 参数 | **PX4 默认** | 模板值 | 方向 | 为什么 |
|---|---|---|---|---|
| `GF_ACTION` | 2（返航） | 2 | 不变 | 默认已是返航，合理 |
| `GF_MAX_HOR_DIST` | **0** | 100 | **从关到开** | **0 = 围栏关闭** |
| `COM_RC_LOSS_T` | **0.5 s** | 5 | **放宽** | 默认太短，正常链路抖动就误触发 |
| `NAV_RCL_ACT` | 2（返航） | 2 | 不变 | 合理 |
| `COM_LOW_BAT_ACT` | **0（只警告）** | 2（返航） | **从警告到动作** | 默认不会自动返航 |

**四条里有一条最危险**：

```text
GF_MAX_HOR_DIST = 0    →  地理围栏根本没启用
```

**这意味着**：如果你"什么都没配"，飞控**没有水平围栏保护**。你以为有，其实没有。

**第二条同样危险**：

```text
COM_LOW_BAT_ACT = 0    →  低电量只发警告，不自动返航
```

电池快没电时，飞控会提示你，但**不会自己回来**。如果此时链路断了，飞机就丢在那里。

**第三条是"反方向"的调整**：

`COM_RC_LOSS_T` 默认 **0.5 秒**——这个值在实机上过于激进：图传/遥控偶尔丢一帧就被判定失联，飞机会不停地触发返航。模板改成 5 秒是**放宽**，属于"降低误报"。

> **所以"改参数"不总是"改得更严格"**：有的是把关闭改开启，有的是把过敏改迟钝。**每一项都要问一句"默认值为什么是这个"。**

**怎么自己查**：这套仓库自带 PX4 源码，直接 grep：

```bash
grep -rn "PARAM_DEFINE_INT32(GF_ACTION" PX4-Autopilot/src/
grep -rn "PARAM_DEFINE_FLOAT(COM_RC_LOSS_T" PX4-Autopilot/src/
```

**参数说明在源码注释里**（`@unit`、`@min`、`@max`、`@group`），比任何二手文档都准确。

### 1.4 实测：这份检查的输出长什么样

在写好本章的环境里实跑一次：


## 2. 差距到底在哪几层

### 2.1 状态估计：从"完美收敛"到"一直在打架"

| 项 | 仿真 | 实机 |
|---|---|---|
| GPS | 无误差 | 多路径反射、城市峡谷、精度漂移 |
| 磁力计 | 无干扰 | 电机线缆、金属机架、地面钢筋 |
| IMU | 无振动 | 机架振动、桨不平衡、谐振 |
| EKF | 收敛快、可重置 | 收敛慢、重置后要重新稳定 |

**症状**：飞机"漂"、高度不稳、航向缓慢偏转、解锁被拒（预检不过）。

**对应课程内容**：第 2 章 `ekf_stable` 门控、第 4 章"贴地爬行"——那些坑在实机上会**更频繁**出现。

### 2.2 执行器：从"理想电机"到"有脾气"

| 项 | 仿真 | 实机 |
|---|---|---|
| 电机响应 | 瞬时 | 有加速延迟（几十毫秒） |
| 死区 | 无 | 低油门不转 |
| 电池 | 恒定电压 | 压降导致推力下降 |
| 桨效 | 理想 | 地效、前飞效率变化 |

**症状**：定点悬停抖动、爬高比预期慢、低电量时"掉高"。

**为什么重要**：仿真里调好的 PID 增益，上机很可能**过大**——实机有延迟，大增益会振荡。

### 2.3 坐标系与外参：仿真里的"理想值"

课程反复讲四套坐标系：

```text
ENU(gz/ROS) ↔ NED(PX4) ↔ 机体系(FLU) ↔ 光心系(相机)
```

仿真里，相机装在机体哪个位置、朝哪个方向，是**世界文件写死的理想值**。

实机里，这些都要**实测标定**：

| 外参 | 标定什么 | 不标的后果 |
|---|---|---|
| 相机-IMU | 相对位置与朝向 | VIO 漂移、测距错 |
| 相机-机体 | 安装偏移 | 精准降落偏几厘米到几十厘米 |
| IMU-机体 | 安装角 | 姿态估计系统性偏差 |

**症状**：视觉测距总是偏一个固定量；降落总落在同一侧。

**对应课程内容**：第 6 章"符号必须实测"——外参就是"更正式的实测"。

### 2.4 通信：从"本地 DDS"到"数传链路"

| 项 | 仿真 | 实机 |
|---|---|---|
| 链路 | 本机内存/UDP | 数传电台 / WiFi / 4G |
| 带宽 | 充足 | 受限（几 kbps–几 Mbps） |
| 丢包 | 几乎为零 | 常见 |
| 延迟 | 毫秒级 | 几十到几百毫秒 |

**症状**：Offboard 心跳断续 → 触发 failsafe → 自动降落或返航。

**这推翻了一个假设**：第 2 章说"心跳必须 > 2Hz 持续"，仿真里轻松做到；实机一旦丢包，就可能被判"外部控制器掉线"。

**应对**：把关键控制逻辑放进飞控（第 14 章的"注册自定义模式"路线），而不是全靠外部节点。

### 2.5 安全：从"撞了重来"到"桨会伤人"

这是**性质完全不同**的一层。

| 项 | 仿真 | 实机 |
|---|---|---|
| 失败成本 | 重启仿真 | 炸机、伤人、火灾 |
| 边界 | 虚拟墙 | 物理围栏、人员隔离 |
| 急停 | 杀进程 | 物理急停开关 |

**所以顺序是**：**围栏 + 急停 + 监督层，必须先于首飞**。

这也是第 11 章为什么把安全监督单独成章——它不是"高级功能"，是**前置条件**。

### 2.6 第 8 章的 VIO 失败，就是一次 sim2real 预演

回头看第 8 章：VINS-Fusion 是为**实机（RealSense D435i）**调校的，喂给它"过于理想"的仿真数据，反而初始化失败。

这揭示了一个反直觉的事实：

> **仿真不是"更简单"，而是"另一种分布"**。
> 为真实数据设计的算法，可能在理想数据上失效；反之亦然。

所以 sim2real 不是"把仿真代码搬过去"，而是"**在两套分布之间做校准**"。

### 2.7 一个真实的坐标事故：飞到 58 米外

这是本仓库第 9 章踩过的坑，值得单独讲，因为它是"仿真里也会错、实机上错得更贵"的典型。

**事故**：把 ego-planner（工作在 ENU 系）输出的位置，直接当成 NED 位置喂给 PX4。结果飞机**飞到了 58 米外**。

**为什么**：ENU 与 NED 的轴是**交换**关系，不是旋转关系：

```text
px4_x(N) = gz_y(E)
px4_y(E) = gz_x(N)
px4_z(D) = -gz_z(U)
```

**关键区别**：

| 错误做法 | 结果 |
|---|---|
| 当成"航向差 90°"，做一次旋转 | **错**，因为 x/y 是交换而非旋转 |
| 做轴交换 + z 取负 | 对 |

**为什么容易错**：感觉上"东和北差 90 度，转一下就行"。但 ENU→NED 是**交换两个轴**（外加 z 反向），不是绕 z 轴旋转——两者在数学上不同，旋转会保留"哪个轴是哪个"的顺序。

**验证方法**：让飞机朝已知方向飞 1 米，看 PX4 的 `vehicle_local_position` 增量是不是你能预期的那个轴。

### 2.8 安全层的实机对应

第 11 章的安全监督跑在 ROS2 侧。实机上还有一层**飞控内置**的保护，两者要一起配。

**PX4 侧参数**（QGC 里设置）：

```text
GF_ACTION        = 2      # 围栏动作: 2=返航 1=降落 3=终止
GF_MAX_HOR_DIST  = 100    # 水平围栏 (m)
GF_MAX_VER_DIST  = 120    # 垂直围栏 (m)
COM_RC_LOSS_T    = 5      # 遥控失联超时 (s)
NAV_RCL_ACT      = 2      # 失联动作: 2=返航
COM_DISARM_PRFLT = 10     # 地面未解锁自动上锁
CBRK_FLIGHTTERM  = 0      # 终止开关可用
```

**两层保护的分工**：

| 层 | 管什么 | 例子 |
|---|---|---|
| **飞控内置**（GF/COM/NAV） | 链路、电量、围栏——**即使外部程序死了也生效** | 遥控失联返航 |
| **ROS2 监督层**（第 11 章） | 任务语义与场地约束 | "飞到场地边界就 RTL" |

**为什么要两层**：外部程序可能崩、通信可能断；飞控内置保护不依赖它们。反过来，飞控不知道"这次任务的场地只有 20 米"，所以外部层补语义。

**验证方法（仿真）**：把 `max_radius` 设成 2.5m，跑 3m 航点任务，看是否出现"超出水平围栏 → RTL"。

### 2.9 三个典型的实机故障（按发生概率排序）

**故障一：磁罗盘干扰 → 航向漂移**

| 项 | 内容 |
|---|---|
| 现象 | 起飞后缓慢自转，或"往前飞"却往侧方走 |
| 仿真对应 | 没有（仿真磁场干净） |
| 原因 | 电机线缆电流产生磁场、机架含铁磁材料、地面有钢筋 |
| 处理 | 做磁校准（远离金属）、把磁力计外置（加高支架）、检查电流线走向 |

**为什么危险**：航向是位置控制的基础。航向错，所有"向前/向左"的指令都错——第 9 章那个"飞反"在实机上就是这个后果。

**故障二：机架振动 → 高度抖动**

| 项 | 内容 |
|---|---|
| 现象 | 悬停时高度上下跳，加速度计读数毛刺大 |
| 仿真对应 | 无振动 |
| 原因 | 桨不平衡、电机轴承磨损、机架刚性不足与飞控产生谐振 |
| 处理 | 做桨平衡、加减振棉、调整 `INS_ACCEL_FILTER`/`IMU_GYRO_NF` 滤波 |

**为什么难查**：振动本身看不见，表现为"高度控制不好"，很容易误判成 PID 参数问题——于是越调越糟。

**故障三：数传丢包 → Offboard 掉线**

| 项 | 内容 |
|---|---|
| 现象 | 飞着飞着突然自动降落或返航 |
| 仿真对应 | 本地 DDS 几乎不丢包 |
| 原因 | 数传带宽/距离/干扰导致心跳中断超过阈值 |
| 处理 | 降低发送频率、改飞控内置模式（第 14 章）、加大失联超时（有风险） |

**判断方法**：看日志里 failsafe 的触发原因字段，是"数据链丢失"还是"外部控制丢失"，两者处理方式不同。

**三个故障的共同点**：**仿真里都不存在**。所以不能靠"仿真跑通了"来预判实机——只能靠这份清单逐项排查。

## 3. 参数整定：从仿真值推到实机值

### 3.1 为什么不能照抄

仿真参数是在"无噪声、无延迟、无振动"下调出来的。实机每多一个非理想因素，等效于**给控制器加了延迟和扰动**。

经验方向：

| 参数 | 仿真值 | 上机方向 | 原因 |
|---|---|---|---|
| 位置环 P | 可以偏大 | **先减半** | 延迟导致超调 |
| 速度环 P | 可以偏大 | **先减 30%** | 同上 |
| 加速度限制 | 可以激进 | **先减小** | 电机跟不上 |
| 最大速度 | 可以高 | **先降** | 安全 + 控制余量 |

**原则：上机先"软"（保守），确认稳定后再逐步"硬"（激进）。**

### 3.2 用日志对比而不是"飞一次调一次"

1. 仿真跑同一任务，记录**指令**与**响应**；
2. 实机跑同一任务，记录同样两组；
3. 叠加两条曲线，看差在哪：

| 现象 | 推断 | 对策 |
|---|---|---|
| 指令相同、响应滞后 | 延迟 | 降增益 |
| 响应振荡 | 增益过大 | 降增益 |
| 响应偏慢 | 增益过小或有死区 | 升增益 / 查死区 |

PX4 的 ulog 与仿真日志格式不同，但都能导出"时间-位置-速度"序列，用同一套脚本画图。

### 3.3 整定顺序

```text
姿态环（内环）→ 速度环 → 位置环 → 任务层
```

**必须从内到外**。内环不稳，外环调什么都是白搭——这是第 2 章"姿态控制是内环"的工程含义。

## 4. 迁移路线：四步，不要跳

| 步骤 | 做什么 | 验收标准 |
|---|---|---|
| **1 系留测试** | 绑在架子上，只测电机/传感器/解锁 | 电机转向正确、IMU 方向正确、能解锁 |
| **2 低空悬停** | 1m 高度悬停，不接任务 | 稳定悬停 30 秒，位置漂移 < 1m |
| **3 围栏内自由飞** | 小范围手动/半自动 | 不越界、不失控、急停有效 |
| **4 任务飞行** | 跑课程任务（航点/降落） | 判分指标达标 |

**每步都先跑 `sim2real_check.sh`**，确认环境没变。

**为什么不能跳**：每步验证的是**不同层**——系留测执行器、悬停测估计器、围栏测安全层、任务测集成。跳步会让问题混在一起。

## 6. 逐段读 `sim2real_check.sh`

这个脚本不长，但有几个设计选择值得学。

### 6.1 一行 `chk` 函数承担全部检查

```bash
chk() { if eval "$2" >/dev/null 2>&1; then echo "  [OK]   $1"; OK=$((OK+1));
        else echo "  [FAIL] $1"; FAIL=$((FAIL+1)); fi; }
```

**三个设计点**：

| 点 | 作用 |
|---|---|
| `eval "$2"` | 让检查项以**字符串**形式写在参数里，可读性高 |
| `>/dev/null 2>&1` | **静默执行**，只显示结论不显示过程 |
| `OK/FAIL` 计数 | 最后能给出汇总 |

**为什么静默**：检查项的执行输出（比如 `ls` 的报错）对使用者没意义，他只需要知道"通过没"。**这是"输出面向人，日志面向机器"的取舍**——代价是失败时看不到细节，得自己重跑那条命令。

### 6.2 三组检查的顺序有意义

```text
1. 环境（ROS2 / PX4 / Agent / 两个包）
2. 代码与文档（安全节点 / 文档 / 集群 / 行为树）
3. 生成参数模板
```

**顺序是从"能不能跑"到"功能齐不齐"**：

- 环境不齐，后面全白搭；
- 代码不齐，说明这个仓库的某些章节没法做；
- 参数模板放最后，因为它是"输出物"而不是"检查项"。

### 6.3 `exit 0` 的选择

脚本最后：

```bash
[ "$FAIL" -eq 0 ] && echo "仿真侧已就绪; ..."
exit 0
```

**注意：无论有没有失败，都 `exit 0`。**

| 设计 | 好处 | 坏处 |
|---|---|---|
| `exit 0`（当前） | 当"清单"用，失败也继续往下看全貌 | 不能用在 CI 里当门禁 |
| `exit $FAIL` | 能当门禁（非 0 即失败） | 第一项失败就看不到后面 |

**这是一个真实的取舍**：如果这个脚本要接到 CI 里（"检查不过就不许合并"），就该改成 `exit $FAIL`。**工具的设计取决于它的用途**。

### 6.4 参数模板里一个容易漏的项

```text
EKF2_EV_CTRL     15     # 外部视觉融合 (0=禁用)
```

**`EKF2_EV_CTRL`** 是"外部视觉数据（external vision）融合开关"的位掩码。PX4 源码 `src/modules/ekf2/module.yaml` 给出的位定义：

| 位 | 含义 |
|---|---|
| 0 | 水平位置融合 |
| 1 | 垂直位置融合 |
| 2 | 三维速度融合 |
| 3 | 偏航融合 |

所以 `15 = 1+2+4+8` 表示**四项全开**。

**为什么它重要**：如果你走第 8 章那条 `vehicle_visual_odometry` 路线（用 VIO 替代 GPS），**这个参数不开，飞控根本不理你的视觉数据**——而且不报错。

**这与第 7 章的"静默失败"是同一类问题**：缺一个开关，系统照常运行，只是没在做你想要的事。

### 6.5 这份检查单的边界

诚实地说清它**不能**验证什么：

| 能验证 | 不能验证 |
|---|---|
| 文件在不在 | 文件内容对不对 |
| 包编译了没 | 跑起来行为对不对 |
| 参数模板生成了 | 参数有没有真的写进飞控 |
| — | **实机硬件状态**（电池、桨、电机） |

**所以脚本是"入场券"，不是"通行证"**。真正的放行依据是第 5 节那份六方面检查单 + 现场判断。

## 常见误解

| 误解 | 实际情况 |
|---|---|
| "仿真能飞，实机就能飞" | 四层假设都会被打破 |
| "参数照抄就行" | 实机有延迟，仿真增益通常偏大 |
| "外参可以用 CAD 图算" | 必须实测，装配误差远大于图纸精度 |
| "先飞起来再装安全层" | 安全层必须先行，不可让渡 |
| "仿真数据更简单" | 是"另一种分布"，可能让实机算法失效 |
| "调参靠试飞" | 应先做指令-响应对比，再定点调整 |
| "课程结论可当实机结论" | 本仓库未做真机验证，结论仅限仿真 |

| 1 | `GF_ACTION` | 碰围栏后干什么 | 2=返航，1=降落，3=终止 |
| 2 | `GF_MAX_HOR_DIST` | 水平围栏半径 | **默认 0 = 关闭**，必须设 |
| 3 | `GF_MAX_VER_DIST` | 垂直围栏 | 与限高法规对齐 |
| 4 | `COM_RC_LOSS_T` | 遥控失联判定时间 | **默认 0.5s 太激进**，5s 更稳 |
| 5 | `NAV_RCL_ACT` | 失联后动作 | 2=返航 |
| 6 | `COM_LOW_BAT_ACT` | 低电量动作 | **默认 0 = 只警告**，必须改 |
| 7 | `COM_DISARM_PRFLT` | 未解锁自动上锁 | 防"忘了上锁耗电" |
| 8 | `MPC_XY_VEL_MAX` | 最大水平速度 | 场地小就调小 |
| 9 | `MPC_Z_VEL_MAX_UP` | 最大上升速度 | 影响起飞时间 |
| 10 | `MPC_Z_VEL_MAX_DN` | 最大下降速度 | **比上升小是故意的**（防撞地） |
| 11 | `MPC_XY_P` | 水平位置环增益 | 上机先减半（第 3.1 节） |
| 12 | `MPC_ACC_HOR` | 水平加速度上限 | 电机响应跟不上就减小 |
| 13 | `EKF2_HGT_MODE` | 高度源 | 0=气压 / 1=GPS / 3=视觉 |
| 14 | `EKF2_GPS_CHECK` | GPS 质量检查掩码 | 21 是一组常用位组合 |
| 15 | `EKF2_EV_CTRL` | 外部视觉融合 | 15 = 四项全开（第 6.4 节） |

### 三条"默认值就危险"的

| 参数 | 默认 | 危险在哪 |
|---|---|---|
| `GF_MAX_HOR_DIST` | **0** | 围栏**根本没启用** |
| `COM_LOW_BAT_ACT` | **0** | 低电量**只警告不返航** |
| `COM_OBL_RC_ACT` | **0** | Offboard 丢失后**原地悬停**（不在本模板里，但必须单独设） |

**这三条合起来说明**：

> **PX4 的默认值是"保守但不救你"**——它不会乱动，但也不会自己回家。

### 怎么把模板写进飞控

**方法一：QGC 手动设**（推荐初次）

在 QGC 的"参数"页面逐个搜索并修改。**好处是能看到每一项的说明**。

**方法二：参数文件批量导入**

```bash
# 把模板转成 QGC 能读的格式（每行 参数名,值）
awk '{if ($1 && $1 !~ /^#/) printf "%s,%s\n", $1, $2}' docs/px4_params_template.txt > params.csv
```

然后 QGC → 工具 → 加载/保存参数。

**方法三：SD 卡 `params.txt`**

把参数写进 SD 卡根目录的 `params.txt`，上电自动加载。**适合批量部署**。

### 写完必须做的一件事

**回读确认**——参数真的写进去了吗？

```bash
# QGC 参数页搜索关键字，确认值变了
# 或用 MAVLink 读参数（param show）
```

**为什么必须回读**：写参数失败是静默的。**你以为设了围栏，其实还是 0。**
