## 1. 无人机有哪些类型

按**升力来源**分，常用的是三大类：

| 类型 | 升力怎么来 | 能悬停吗 | 续航 | 典型用途 |
|---|---|---|---|---|
| **多旋翼**（四/六/八旋翼） | 多个螺旋桨直接向上拉 | ✅ 能 | 短（约 20–40 分钟） | 航拍、巡检、本课程 |
| **固定翼** | 机翼靠前进时的气流产生升力 | ❌ 不能（必须一直飞） | 长（1 小时以上） | 测绘、长距离巡查 |
| **复合翼 VTOL** | 多旋翼垂直起降 + 固定翼巡航 | ✅ 起降时能 | 长 | 远程巡检、物流 |

另有无人船、无人车、飞艇等，本课程第 14 章会接触复合翼（VTOL = Vertical Take-Off and Landing，垂直起降）。

**为什么课程从多旋翼开始**：

- 能悬停——"飞到某点停住"是最直观的任务，适合学控制；
- 位置指令直接有效——固定翼必须先有空速才有升力，控制逻辑复杂得多；
- 仿真里摔机零成本——多旋翼的失败模式（掉高、侧翻）现象明显，适合排障教学。

**旋翼数量的含义**：四旋翼（quadcopter）4 个桨、六旋翼（hexacopter）6 个、八旋翼 8 个。桨越多冗余越高（坏一个电机还能降落），但效率和载重比下降。课程里的 `typhoon_h480` 就是六旋翼。

## 2. 四旋翼是怎么飞起来的

### 2.1 四个桨，两顺两逆

四旋翼的四个电机，**两个顺时针转、两个逆时针转**（对角同向）。这样设计是为了抵消反扭矩——桨旋转时会给机身一个反向的扭转力，两顺两逆正好互相抵消，机身才不会自己打转。

### 2.2 三个姿态角：Roll / Pitch / Yaw

"姿态"就是飞机在空中的**朝向**，用三个角描述：

| 角 | 中文 | 绕哪个轴转 | 直观动作 |
|---|---|---|---|
| **Roll** | 横滚 | 前后轴（机头到机尾） | 向左/向右侧倾 |
| **Pitch** | 俯仰 | 左右轴（左翼到右翼） | 机头抬起/低下 |
| **Yaw** | 偏航 | 竖直轴 | 机头左转/右转（原地转向） |

### 2.3 差速：一切动作的原理

四旋翼没有方向盘和舵面，**所有动作都靠四个桨的转速差**：

- **上升/下降**：四个桨同时加速/减速；
- **横滚**：左侧桨减速、右侧桨加速（或反之）→ 机身侧倾；
- **俯仰**：前侧桨与后侧桨差速 → 机头抬起/低下；
- **偏航**：顺时针组与逆时针组的总转速打破平衡 → 反扭矩不再抵消 → 机身转向。

**关键洞察：位置移动靠先倾斜姿态。** 想向前飞，先低头（pitch），升力矢量就向前倾，产生向前的分力。所以飞控必须分两层：外层算"该倾斜多少"，内层算"电机怎么转才能保持这个倾斜"。这就是下一节"姿态控制"的由来。

### 2.4 升力与转速的平方：为什么油门不是线性的

螺旋桨的升力近似正比于**转速的平方**：

```text
升力 ∝ ω²
```

两个直接后果：

**第一，悬停是一个"平衡点"。** 四桨总升力正好等于重力时悬停；低于下降，高于上升。

**第二，油门响应"前松后紧"。** 转速 50%→60%，升力增量小；90%→100%，增量大。所以飞控内部用**推力曲线**把"期望升力"换算成电机指令，而不是线性映射。

**为什么不像直升机用"总距"**：直升机靠改变桨叶迎角调升力，响应快、效率高，但要变距机构；多旋翼靠变转速，结构简单、响应够用，代价是效率略低。消费级无人机几乎都是多旋翼——**简单可靠 > 极致效率**。

## 3. 飞控在干什么：五个职责

第 1 章表格里写 PX4 负责"姿态控制、EKF、模式管理"。展开说，飞控有五个职责，分层协作：

| 层 | 职责 | plain 解释 | 典型频率 |
|---|---|---|---|
| 内环 | **姿态控制** | 让飞机保持目标 Roll/Pitch/Yaw，输出四个电机的转速 | 数百 Hz–1kHz |
| 外环 | **位置/速度控制** | 把"飞到 (3,0,5)"翻译成"该倾斜多少度、朝哪" | 数十 Hz |
| 估计 | **EKF** | 回答"我在哪、多快、什么姿态" | 数百 Hz |
| 管理 | **模式管理** | 决定此刻谁说了算（遥控？程序？自动返航？） | 事件驱动 |
| 保护 | **失效保护（failsafe）** | 失控/低电量/外部掉线时自动保命 | 事件驱动 |

### 3.1 姿态控制与位置控制为什么分两层

姿态变化快（电机毫秒级响应），位置变化慢（飞机惯性大）。分层后：

- 内环只管"稳"，频率极高，不受上层干扰；
- 外环只管"去哪"，输出目标姿态给内环。

你在第 2 章发的 `TrajectorySetpoint`（位置目标）走外环；PX4 内部再转成姿态目标给内环。**你不需要自己算电机转速**——这正是飞控的价值。

### 3.2 EKF：扩展卡尔曼滤波

传感器各有毛病：GPS 会漂移（米级误差）、IMU（加速度计+陀螺仪）积分会累积漂移、气压计受天气影响。**EKF（Extended Kalman Filter，扩展卡尔曼滤波）把这些互相矛盾的测量融合成一个"最可能真实"的状态估计**（位置、速度、姿态）。

- "卡尔曼滤波"是一种递推估计算法：用上一时刻的估计+当前测量，算出更准的当前估计；
- "扩展"指它能处理非线性系统（飞机运动方程是非线性的）。

**为什么局部坐标会"瞬移"**：EKF 需要一个局部原点。当 GPS 跳变太大，它会**重置原点**重新锚定——同一物理位置的局部坐标就变了。这就是第 4、7 章"贴地爬行"坑的根源，也是课程坚持用 Gazebo 世界系真值判分的原因。

### 3.3 模式管理：飞控是个状态机

PX4 同一时刻只处于一种模式，常见的：

| 模式 | 谁在控制 | 说明 |
|---|---|---|
| Manual / Stabilized | 遥控器 | 人工飞，Stabilized 帮你稳姿态 |
| Altitude / Position | 遥控器+飞控 | 飞控帮你保持高度/位置 |
| **Offboard** | **外部程序** | 你的 ROS2 节点发设定点（第 2 章） |
| RTL | 飞控自动 | Return To Launch，自动返航 |
| LAND | 飞控自动 | 原地降落 |

**为什么需要模式**：安全兜底。程序崩了、心跳断了，飞控能切回安全模式，而不是跟着程序一起失控。

### 3.4 失效保护（failsafe）

触发条件例如：遥控信号丢失、电池过低、**Offboard 心跳/设定点流中断**。最后一条就是第 2 章"必须先预流、持续发心跳"的原因——流一断，PX4 判定外部控制器掉线，触发保护（课程配置下表现为拒绝切换或自动降落）。

### 3.5 EKF 的"预测-更新"：为什么它既信传感器又信模型

EKF 的每一轮都做两件事：

| 步骤 | 做什么 | 直觉 |
|---|---|---|
| **预测** | 用运动模型推算"我现在应该在哪" | 相信物理定律 |
| **更新** | 用传感器测量修正这个预测 | 相信观测 |

**为什么两者都要**：

- 只信模型：IMU 积分会漂，飞一分钟就差几十米；
- 只信传感器：GPS 一秒才更新一次，中间的空档没法用。

EKF 用**协方差**表示"我有多不确定"：模型预测后不确定度变大，传感器来了不确定度变小。每次融合都按"谁更不确定就少信谁"来加权。

**这就解释了"原点重置"**：当 GPS 跳变到远超预期（协方差爆掉），滤波器判断"我的局部坐标基准错了"，于是重建原点。重建之后，同一物理位置的坐标值会突然变化——**这不是 bug，是重新锚定**。

### 3.6 控制带宽：为什么不同环节的频率差这么多

把本章提到的频率排一下：

| 环节 | 典型频率 | 为什么 |
|---|---|---|
| 电机/角速率环 | 1 kHz | 最快，抗扰动 |
| 姿态环 | 250–500 Hz | 保持朝向 |
| 位置环 | 50–100 Hz | 惯性大，不需要太快 |
| 视觉/激光 | 10–30 Hz | 传感器本身慢 |
| 任务层 | 1–10 Hz | 决策不需要快 |

**规律**：越靠近"物理"越快，越靠近"决策"越慢。

**为什么不能反过来**：位置环如果跑 1kHz，它每一步都拿不到新的位置测量，等于在"空转"；姿态环如果只跑 10Hz，风一吹就来不及修正。

**这条规律也解释了第 5 章的现象**：YOLO 推理再快，也快不过 20Hz 的相机；所以视觉类任务的带宽上限是**传感器给的**，不是算力给的。

## 4. 为什么叫这些名字

课程里的名字大多有真实来源，不是随便起的：

| 名字 | 来源与含义 |
|---|---|
| **x500** | PX4 标准四旋翼模型，"500" 指 **500mm 轴距**（对角电机间距），是行业常见的机架尺寸级别 |
| **iris** | 以 3DR Iris 消费级四旋翼为原型的模型（Gazebo Classic 时代常用） |
| **typhoon_h480** | 以 Yuneec Typhoon H480 **六旋翼**为原型 |
| **standard_vtol** | PX4 标准复合翼模型 |
| **gz_ 前缀** | XTDrone2 对新版 Gazebo（gz）机型的命名约定，区别于 Classic 模型 |
| **SITL** | Software-In-The-Loop：固件编译成电脑程序，传感器/执行器用仿真替代 |
| **NED** | North-East-Down（北-东-地）：航空惯例，z 向下为正 |
| **ENU** | East-North-Up（东-北-上）：机器人/ROS 惯例，z 向上为正 |
| **Offboard** | "板外"：控制指令来自飞控板**之外**的计算机 |
| **MAVLink** | Micro Air Vehicle Link：无人机领域通信协议，PX4 命令走它 |
| **DDS** | Data Distribution Service：ROS2 底层的发布/订阅中间件标准 |
| **uXRCE-DDS** | micro XRCE-DDS：面向嵌入式的轻量 DDS，PX4 侧用它，所以需要 Agent 翻译 |

记住两条最有用的：**x500 = 500mm 轴距四旋翼**；**NED 的 z 向下为正，所以 5m 高度写作 z=-5**。

## 5. 软件生态：每个组件一句话

| 组件 | 一句话 |
|---|---|
| **PX4** | 开源飞控固件，管姿态/位置/估计/模式（本章第 3 节） |
| **Gazebo Harmonic** | 物理仿真器，提供重力、碰撞、传感器数据和画面 |
| **ROS2** | 机器人软件框架：节点、话题、参数、launch，你的任务代码跑在它上面 |
| **MicroXRCEAgent** | PX4(uXRCE-DDS) 与 ROS2(DDS) 之间的翻译代理 |
| **px4_msgs** | PX4 消息的 ROS2 定义（VehicleStatus 等），版本必须与 PX4 配套 |
| **XTDrone2** | 北大团队的仿真平台：机型/世界/通信/控制节点，本课程的平台层 |
| **colcon** | ROS2 的编译工具，`colcon build` 编译工作区 |

它们的关系就是第 1 章图 1.3 的数据链路：Gazebo ↔ PX4 ↔ Agent ↔ 你的 ROS2 节点。

15. NED 的三个字母分别是什么？z 朝哪？
16. Offboard 的字面意思是什么？
17. SITL 是什么的缩写？和真机什么关系？
18. MAVLink 是做什么的？
19. uXRCE-DDS 和 DDS 是什么关系？
20. 为什么必须有 MicroXRCEAgent？

---

**答案区**

1. 多旋翼靠螺旋桨直接向下推空气获得反作用力（可悬停）；固定翼靠前进时气流流过机翼产生升力（不能悬停）。
2. 抵消螺旋桨旋转给机身带来的反扭矩，否则机身会自己打转。
3. Roll 绕前后轴（机身纵轴）；Pitch 绕左右轴（横轴）；Yaw 绕竖直轴。
4. 升力方向垂直于机体平面；低头后升力有了向前分量，才会产生前飞。
5. 升力正比于转速的平方（ω²）。
6. 变距机构复杂、成本高、维护难；变转速结构简单可靠，效率虽低但够用。
7. 姿态控制、位置/速度控制、状态估计（EKF）、模式管理、失效保护。
8. 姿态是内环，位置是外环。
9. 预测信运动模型（物理规律）；更新信传感器测量。
10. 估计的不确定度变大，说明该状态"更没把握"。
11. GPS 跳变过大时，滤波器判断局部基准已不可信，重建原点（重新锚定）。
12. 保证"谁在控制"是明确的，并在异常时能切回安全模式。
13. 遥控失联、低电量、外部控制器（Offboard）心跳中断。
14. 500 mm 轴距（对角电机间距）。
15. North-East-Down；z 向下为正。
16. "板外"——控制指令来自飞控板之外的计算机。
17. Software-In-The-Loop；把固件编译成电脑程序 + 仿真传感器，与真机同源码。
18. 无人机领域的通信协议，PX4 的命令（解锁/切模式/返航）走它。
19. uXRCE-DDS 是面向嵌入式的轻量 DDS 方言；ROS2 用标准 DDS，两者需要转换。
20. 没有它，PX4 的 uXRCE-DDS 数据无法变成 ROS2 话题，节点看不到任何 `/fmu/` 消息。
