## 1. 无人机有哪些类型

按**升力来源**分，常用的是三大类：

| 类型 | 升力怎么来 | 能悬停吗 | 续航 | 典型用途 |
|---|---|---|---|---|
| **多旋翼**（四/六/八旋翼） | 多个螺旋桨直接向上拉 | ✅ 能 | 短（约 20–40 分钟） | 航拍、巡检、本课程 |
| **固定翼** | 机翼靠前进时的气流产生升力 | ❌ 不能（必须一直飞） | 长（1 小时以上） | 测绘、长距离巡查 |
| **复合翼 VTOL** | 多旋翼垂直起降 + 固定翼巡航 | ✅ 起降时能 | 长 | 远程巡检、物流 |

另有无人船、无人车、飞艇等，本课程第 14 章会接触复合翼（VTOL = Vertical Take-Off and Landing，垂直起降）。

**为什么课程从多旋翼开始**：

- 能悬停——"飞到某点停住"是最直观的任务，适合学控制；
- 位置指令直接有效——固定翼必须先有空速才有升力，控制逻辑复杂得多；
- 仿真里摔机零成本——多旋翼的失败模式（掉高、侧翻）现象明显，适合排障教学。

**旋翼数量的含义**：四旋翼（quadcopter）4 个桨、六旋翼（hexacopter）6 个、八旋翼 8 个。桨越多冗余越高（坏一个电机还能降落），但效率和载重比下降。课程里的 `typhoon_h480` 就是六旋翼。

## 2. 四旋翼是怎么飞起来的

### 2.1 四个桨，两顺两逆

四旋翼的四个电机，**两个顺时针转、两个逆时针转**（对角同向）。这样设计是为了抵消反扭矩——桨旋转时会给机身一个反向的扭转力，两顺两逆正好互相抵消，机身才不会自己打转。

### 2.2 三个姿态角：Roll / Pitch / Yaw

"姿态"就是飞机在空中的**朝向**，用三个角描述：

| 角 | 中文 | 绕哪个轴转 | 直观动作 |
|---|---|---|---|
| **Roll** | 横滚 | 前后轴（机头到机尾） | 向左/向右侧倾 |
| **Pitch** | 俯仰 | 左右轴（左翼到右翼） | 机头抬起/低下 |
| **Yaw** | 偏航 | 竖直轴 | 机头左转/右转（原地转向） |

### 2.3 差速：一切动作的原理

四旋翼没有方向盘和舵面，**所有动作都靠四个桨的转速差**：

- **上升/下降**：四个桨同时加速/减速；
- **横滚**：左侧桨减速、右侧桨加速（或反之）→ 机身侧倾；
- **俯仰**：前侧桨与后侧桨差速 → 机头抬起/低下；
- **偏航**：顺时针组与逆时针组的总转速打破平衡 → 反扭矩不再抵消 → 机身转向。

**关键洞察：位置移动靠先倾斜姿态。** 想向前飞，先低头（pitch），升力矢量就向前倾，产生向前的分力。所以飞控必须分两层：外层算"该倾斜多少"，内层算"电机怎么转才能保持这个倾斜"。这就是下一节"姿态控制"的由来。

### 2.4 升力与转速的平方：为什么油门不是线性的

螺旋桨的升力近似正比于**转速的平方**：

```text
升力 ∝ ω²
```

两个直接后果：

**第一，悬停是一个"平衡点"。** 四桨总升力正好等于重力时悬停；低于下降，高于上升。

**第二，油门响应"前松后紧"。** 转速 50%→60%，升力增量小；90%→100%，增量大。所以飞控内部用**推力曲线**把"期望升力"换算成电机指令，而不是线性映射。

**为什么不像直升机用"总距"**：直升机靠改变桨叶迎角调升力，响应快、效率高，但要变距机构；多旋翼靠变转速，结构简单、响应够用，代价是效率略低。消费级无人机几乎都是多旋翼——**简单可靠 > 极致效率**。

### 2.5 任务决定机型：五个典型组合

"哪个机型最好"是个伪问题——**没有最好，只有匹配**。

| 任务 | 需要什么能力 | 合适机型 | 为什么 |
|---|---|---|---|
| 航拍 | 稳定悬停 + 相机 | 四旋翼 + 云台 | 悬停稳、控制简单 |
| 室内巡检 | 无 GPS 定位 + 避障 | 四旋翼 + 激光/深度 | 空间小，要精确定位 |
| 物流 | 载重 + 航程 | 六旋翼 / VTOL | 多桨载重，VTOL 省电 |
| 测绘 | 长航时 + 正下视 | 固定翼 / VTOL | 续航是关键 |
| 竞速 | 高机动 | 小轴距四旋翼 | 推重比高、惯性小 |

**三条匹配规律**：

| 需求 | 倾向 |
|---|---|
| 要悬停/低速精确 | 多旋翼 |
| 要续航/速度 | 固定翼或 VTOL |
| 要载重/冗余 | 桨越多越好（但越重越费电） |

**课程为什么全程用 x500（500mm 轴距四旋翼）**：它通用性最好——能悬停、能装多种传感器、控制难度适中。**教学需要一个覆盖大多数任务的基础平台**，而不是每章换一种机型。

**但课程也让你看到边界**：第 14 章换 VTOL，就是因为"多旋翼飞不快、续航短"这个硬限制。

**这条规律在第 4 章会变成一条明确的契约**：

```text
任务 = 机型 + 世界 + 指标
```

三者不匹配，就会出现"代码能跑、结果不对"——比如用前置相机做精准降落（看不到地面）。

### 2.6 续航是怎么算出来的

初学者常问"能飞多久"。这不是一个固定数，而是**载荷、电池、飞行方式**三者共同决定的。

**第一步：算可用能量**

```text
能量(Wh) = 电压(V) × 容量(Ah)
```

例：6S 电池（22.2V 标称）、5000mAh = 5Ah：

```text
能量 = 22.2 × 5 = 111 Wh
```

**第二步：算悬停功率**

多旋翼悬停功率大致与"总重量的 1.5 次方"成正比（悬停效率的经验关系）。重量翻倍，功率约增加 2.8 倍。

**第三步：算时间**

```text
续航(h) = 可用能量(Wh) × 放电深度 / 平均功率(W)
```

**注意"放电深度"**：不能把电池放空（会损坏），实际只用 70–80%。

**一个具体算例**：

| 项 | 值 |
|---|---|
| 电池 | 6S 5000mAh，111 Wh |
| 可用（80%） | 89 Wh |
| 悬停功率 | 约 350 W |
| **理论悬停时间** | 89 / 350 ≈ **0.25 h ≈ 15 分钟** |

**这解释了为什么多旋翼续航只有 15–30 分钟**——不是电池不行，是**悬停本身就很费电**（要持续向下推空气来抵消重力）。

**载荷的代价**：

| 加 200g 载荷 | 影响 |
|---|---|
| 悬停功率 | 约 +10% |
| 续航 | 约 −9% |
| 机动性 | 下降（推重比降低） |

**所以"载重"和"续航"是直接冲突的**——这也是第 14 章为什么要换 VTOL：**固定翼靠机翼产生升力，不用一直推空气，效率高一个量级**。

**固定翼的续航怎么算**：完全不同——它靠"前进速度 × 升阻比"决定，巡航时功率只有多旋翼的几分之一，所以能飞 1 小时以上。

**这门课不要求你算准续航**，但要知道：**看到"续航 40 分钟"的宣传，先问"空载还是满载、悬停还是巡航"。**

## 3. 飞控在干什么：五个职责

第 1 章表格里写 PX4 负责"姿态控制、EKF、模式管理"。展开说，飞控有五个职责，分层协作：

| 层 | 职责 | plain 解释 | 典型频率 |
|---|---|---|---|
| 内环 | **姿态控制** | 让飞机保持目标 Roll/Pitch/Yaw，输出四个电机的转速 | 数百 Hz–1kHz |
| 外环 | **位置/速度控制** | 把"飞到 (3,0,5)"翻译成"该倾斜多少度、朝哪" | 数十 Hz |
| 估计 | **EKF** | 回答"我在哪、多快、什么姿态" | 数百 Hz |
| 管理 | **模式管理** | 决定此刻谁说了算（遥控？程序？自动返航？） | 事件驱动 |
| 保护 | **失效保护（failsafe）** | 失控/低电量/外部掉线时自动保命 | 事件驱动 |

### 3.1 姿态控制与位置控制为什么分两层

姿态变化快（电机毫秒级响应），位置变化慢（飞机惯性大）。分层后：

- 内环只管"稳"，频率极高，不受上层干扰；
- 外环只管"去哪"，输出目标姿态给内环。

你在第 2 章发的 `TrajectorySetpoint`（位置目标）走外环；PX4 内部再转成姿态目标给内环。**你不需要自己算电机转速**——这正是飞控的价值。

### 3.2 EKF：扩展卡尔曼滤波

传感器各有毛病：GPS 会漂移（米级误差）、IMU（加速度计+陀螺仪）积分会累积漂移、气压计受天气影响。**EKF（Extended Kalman Filter，扩展卡尔曼滤波）把这些互相矛盾的测量融合成一个"最可能真实"的状态估计**（位置、速度、姿态）。

- "卡尔曼滤波"是一种递推估计算法：用上一时刻的估计+当前测量，算出更准的当前估计；
- "扩展"指它能处理非线性系统（飞机运动方程是非线性的）。

**为什么局部坐标会"瞬移"**：EKF 需要一个局部原点。当 GPS 跳变太大，它会**重置原点**重新锚定——同一物理位置的局部坐标就变了。这就是第 4、7 章"贴地爬行"坑的根源，也是课程坚持用 Gazebo 世界系真值判分的原因。

### 3.3 模式管理：飞控是个状态机

PX4 同一时刻只处于一种模式，常见的：

| 模式 | 谁在控制 | 说明 |
|---|---|---|
| Manual / Stabilized | 遥控器 | 人工飞，Stabilized 帮你稳姿态 |
| Altitude / Position | 遥控器+飞控 | 飞控帮你保持高度/位置 |
| **Offboard** | **外部程序** | 你的 ROS2 节点发设定点（第 2 章） |
| RTL | 飞控自动 | Return To Launch，自动返航 |
| LAND | 飞控自动 | 原地降落 |

**为什么需要模式**：安全兜底。程序崩了、心跳断了，飞控能切回安全模式，而不是跟着程序一起失控。

### 3.4 失效保护（failsafe）

触发条件例如：遥控信号丢失、电池过低、**Offboard 心跳/设定点流中断**。最后一条就是第 2 章"必须先预流、持续发心跳"的原因——流一断，PX4 判定外部控制器掉线，触发保护（课程配置下表现为拒绝切换或自动降落）。

### 3.5 EKF 的"预测-更新"：为什么它既信传感器又信模型

EKF 的每一轮都做两件事：

| 步骤 | 做什么 | 直觉 |
|---|---|---|
| **预测** | 用运动模型推算"我现在应该在哪" | 相信物理定律 |
| **更新** | 用传感器测量修正这个预测 | 相信观测 |

**为什么两者都要**：

- 只信模型：IMU 积分会漂，飞一分钟就差几十米；
- 只信传感器：GPS 一秒才更新一次，中间的空档没法用。

EKF 用**协方差**表示"我有多不确定"：模型预测后不确定度变大，传感器来了不确定度变小。每次融合都按"谁更不确定就少信谁"来加权。

**这就解释了"原点重置"**：当 GPS 跳变到远超预期（协方差爆掉），滤波器判断"我的局部坐标基准错了"，于是重建原点。重建之后，同一物理位置的坐标值会突然变化——**这不是 bug，是重新锚定**。

### 3.6 控制带宽：为什么不同环节的频率差这么多

把本章提到的频率排一下：

| 环节 | 典型频率 | 为什么 |
|---|---|---|
| 电机/角速率环 | 1 kHz | 最快，抗扰动 |
| 姿态环 | 250–500 Hz | 保持朝向 |
| 位置环 | 50–100 Hz | 惯性大，不需要太快 |
| 视觉/激光 | 10–30 Hz | 传感器本身慢 |
| 任务层 | 1–10 Hz | 决策不需要快 |

**规律**：越靠近"物理"越快，越靠近"决策"越慢。

**为什么不能反过来**：位置环如果跑 1kHz，它每一步都拿不到新的位置测量，等于在"空转"；姿态环如果只跑 10Hz，风一吹就来不及修正。

**这条规律也解释了第 5 章的现象**：YOLO 推理再快，也快不过 20Hz 的相机；所以视觉类任务的带宽上限是**传感器给的**，不是算力给的。

## 4. 为什么叫这些名字

课程里的名字大多有真实来源，不是随便起的：

| 名字 | 来源与含义 |
|---|---|
| **x500** | PX4 标准四旋翼模型，"500" 指 **500mm 轴距**（对角电机间距），是行业常见的机架尺寸级别 |
| **iris** | 以 3DR Iris 消费级四旋翼为原型的模型（Gazebo Classic 时代常用） |
| **typhoon_h480** | 以 Yuneec Typhoon H480 **六旋翼**为原型 |
| **standard_vtol** | PX4 标准复合翼模型 |
| **gz_ 前缀** | XTDrone2 对新版 Gazebo（gz）机型的命名约定，区别于 Classic 模型 |
| **SITL** | Software-In-The-Loop：固件编译成电脑程序，传感器/执行器用仿真替代 |
| **NED** | North-East-Down（北-东-地）：航空惯例，z 向下为正 |
| **ENU** | East-North-Up（东-北-上）：机器人/ROS 惯例，z 向上为正 |
| **Offboard** | "板外"：控制指令来自飞控板**之外**的计算机 |
| **MAVLink** | Micro Air Vehicle Link：无人机领域通信协议，PX4 命令走它 |
| **DDS** | Data Distribution Service：ROS2 底层的发布/订阅中间件标准 |
| **uXRCE-DDS** | micro XRCE-DDS：面向嵌入式的轻量 DDS，PX4 侧用它，所以需要 Agent 翻译 |

记住两条最有用的：**x500 = 500mm 轴距四旋翼**；**NED 的 z 向下为正，所以 5m 高度写作 z=-5**。

### 4.1 还会遇到的六个名字

| 名字 | 全称/来源 | 一句话 |
|---|---|---|
| **EKF2** | Extended Kalman Filter 第 2 代 | PX4 的状态估计器；名字里的 2 是版本，不是"2 个" |
| **uORB** | micro Object Request Broker | PX4 内部的发布订阅总线，飞控各模块靠它交换数据 |
| **HITL** | Hardware-In-The-Loop | 飞控用真实硬件、传感器用仿真；SITL 的"半实物"版本 |
| **PWM** | Pulse Width Modulation | 传统电机/舵机信号，占空比表示指令 |
| **DShot** | Digital Shot | 数字式电调协议，比 PWM 精确、抗干扰 |
| **QGC** | QGroundControl | 地面站软件，用于参数配置、校准、看状态 |

**为什么值得认这些名字**：你会在日志、参数名、报错里反复遇到它们。比如 `EKF2_HGT_MODE` 就是"EKF2 的高度源模式"——拆开看就懂了。

**一个实用技巧**：PX4 参数名有统一前缀（`EKF2_`、`MPC_`、`COM_`、`GF_`、`NAV_`、`SYS_`），看到前缀就知道属于哪个子系统：

| 前缀 | 子系统 |
|---|---|
| `EKF2_` | 状态估计 |
| `MPC_` | 多旋翼位置控制 |
| `COM_` | 通信/通用 |
| `GF_` | 地理围栏 |
| `NAV_` | 导航 |
| `SYS_` | 系统 |

第 15 章那张参数模板表，就是按这个规律读的。

## 5. 软件生态：每个组件一句话

| 组件 | 一句话 |
|---|---|
| **PX4** | 开源飞控固件，管姿态/位置/估计/模式（本章第 3 节） |
| **Gazebo Harmonic** | 物理仿真器，提供重力、碰撞、传感器数据和画面 |
| **ROS2** | 机器人软件框架：节点、话题、参数、launch，你的任务代码跑在它上面 |
| **MicroXRCEAgent** | PX4(uXRCE-DDS) 与 ROS2(DDS) 之间的翻译代理 |

| **XTDrone2** | 北大团队的仿真平台：机型/世界/通信/控制节点，本课程的平台层 |
| **colcon** | ROS2 的编译工具，`colcon build` 编译工作区 |

它们的关系就是第 1 章图 1.3 的数据链路：Gazebo ↔ PX4 ↔ Agent ↔ 你的 ROS2 节点。

### 5.1 一条控制指令的完整旅程

把上面这张表串成一个故事：你的节点想让飞机升高 1 米。

| 步 | 发生什么 | 谁在做 | 数据形态 |
|---|---|---|---|
| 1 | 你的代码算出目标点 `(0, 0, -4)` | 你的 ROS2 节点 | Python 变量 |
| 2 | 打包成 `TrajectorySetpoint` 发出去 | 你的节点 | ROS2 话题消息 |
| 3 | 转成 uXRCE-DDS 格式 | MicroXRCEAgent | DDS 序列化字节 |
| 4 | 飞控内部的 uORB 总线收到 | PX4 | 内部消息 |
| 5 | 位置控制器算"该往哪走" | PX4 | 期望速度/加速度 |
| 6 | 姿态控制器算"该倾斜多少" | PX4 | 期望姿态角 |
| 7 | 角速率控制器算"各电机转多快" | PX4 | 四个 PWM 值 |
| 8 | 电机转速改变，升力变化 | 电机 + 桨 | 物理量 |
| 9 | 飞机升高，传感器读到新状态 | IMU/气压计 | 电信号 |
| 10 | 状态被估计、打包、回传 | PX4 → Agent → ROS2 | 话题消息 |

**这条链路说明三件事**：

1. **你只控制"目标"**，剩下的（该倾斜多少、电机转多快）飞控全包了；
2. **每一层都有延迟**（第 3 章的控制带宽表就是这么来的）；
3. **任一环断了，整条链就断**——这也是为什么"没反应"要逐段排查，不能只看最后一步。

### 5.2 为什么要有这么多层

初学者常问："为什么不能直接给电机写 PWM？"

能，但你会失去这些：

| 层 | 提供什么 | 失去它的后果 |
|---|---|---|
| 姿态控制 | 抗风、抗扰动 | 手动一直修正 |
| 状态估计（EKF） | 知道自己在哪 | 只能盲飞 |
| 模式管理 | 失控时切安全模式 | 出事无人兜底 |
| Agent | ROS2 与 PX4 互通 | 只能用地面站 |
| 仿真器 | 无限次试错 | 每摔一次损失一台机器 |

**分层的本质是"把不常变的东西固化在下面，把常变的东西放在上面"**。姿态控制在固件里（几乎不改），任务逻辑在 ROS2 里（天天改）。

**这也解释了课程的结构**：第 1–4 章在"上面"写任务，第 7–13 章在"中间"加感知与规划，第 11、15 章回到"下面"谈安全与实机。

### 3.7 一个控制周期里发生了什么

前两节讲"有哪些模块"，这一节讲"它们以什么顺序跑"。

以 250 Hz 的姿态环为例，一个周期 4 毫秒：

| 顺序 | 动作 | 耗时量级 |
|---|---|---|
| 1 | 读 IMU（最新一次采样） | 微秒 |
| 2 | 状态估计（EKF 预测+更新） | 几十微秒 |
| 3 | 姿态控制器算期望角速率 | 几微秒 |
| 4 | 角速率控制器算各电机指令 | 几微秒 |
| 5 | 混控（把"力矩+推力"分配成四个电机） | 几微秒 |
| 6 | 写电调（PWM/DShot） | 微秒–毫秒 |

**关键点：这 4 毫秒里，飞控不能被打断。** 所以飞控固件是**实时系统**——任务按固定优先级调度，绝不用"等一会儿"的方式阻塞。

**为什么这跟你的 ROS2 节点有关**：

| 层 | 周期 | 谁保证实时 |
|---|---|---|
| 电机/角速率 | ~1 kHz | 飞控固件（硬实时） |
| 姿态 | 250–500 Hz | 飞控固件 |
| 位置 | 50–100 Hz | 飞控固件 |
| **Offboard 设定点** | **你决定（课程用 10 Hz）** | **你的节点（软实时）** |
| 任务决策 | 1–10 Hz | 你的节点 |

**你的节点只需要跑 10 Hz**，因为位置环在飞控里跑得更快，它负责把"10 Hz 的位置目标"平滑成连续运动。

**反过来说**：如果你发设定点的频率掉到 1 Hz 以下，飞控就会判定"外部控制丢失"（第 2 章的 `COM_OF_LOSS_T = 1.0s`）。

**这就是"每个模块的周期要匹配它的职责"**——快了浪费，慢了失效。

### 3.8 为什么飞控不能跑在 Linux 上（而仿真可以）

一个常被问到的问题：既然 SITL 是在电脑上跑的，为什么真机要用专门的飞控芯片？

| 维度 | 飞控 MCU | Linux 电脑 |
|---|---|---|
| 实时性 | 硬实时（微秒级抖动） | 软实时（毫秒级抖动，会被调度打断） |
| 启动时间 | 毫秒级 | 数秒到数十秒 |
| 可靠性 | 无后台进程干扰 | 可能被更新/日志/网络卡住 |
| 功耗 | 毫瓦级 | 瓦级 |

**为什么仿真可以**：SITL 里"物理世界"也是软件模拟的，时间可以放慢/对齐。**抖动不会导致坠机，只会让仿真跑得不准。**

**为什么真机不行**：姿态环 4ms 的周期里如果被 Linux 调度打断 20ms，飞机已经翻了。

**所以真机架构通常是"双脑"**：

```text
飞控（MCU，硬实时）  ←→  机载电脑（Linux，跑 ROS2/视觉）
     保命                     干活
```

**这也解释了第 15 章为什么强调"关键逻辑要能跑在飞控里"**——外部电脑是不可靠的。

**答案区**

1. 多旋翼靠螺旋桨直接向下推空气获得反作用力（可悬停）；固定翼靠前进时气流流过机翼产生升力（不能悬停）。

3. Roll 绕前后轴（机身纵轴）；Pitch 绕左右轴（横轴）；Yaw 绕竖直轴。
4. 升力方向垂直于机体平面；低头后升力有了向前分量，才会产生前飞。
5. 升力正比于转速的平方（ω²）。
6. 变距机构复杂、成本高、维护难；变转速结构简单可靠，效率虽低但够用。
7. 姿态控制、位置/速度控制、状态估计（EKF）、模式管理、失效保护。
8. 姿态是内环，位置是外环。
9. 预测信运动模型（物理规律）；更新信传感器测量。
10. 估计的不确定度变大，说明该状态"更没把握"。
11. GPS 跳变过大时，滤波器判断局部基准已不可信，重建原点（重新锚定）。
12. 保证"谁在控制"是明确的，并在异常时能切回安全模式。
13. 遥控失联、低电量、外部控制器（Offboard）心跳中断。
14. 500 mm 轴距（对角电机间距）。
15. North-East-Down；z 向下为正。
16. "板外"——控制指令来自飞控板之外的计算机。
17. Software-In-The-Loop；把固件编译成电脑程序 + 仿真传感器，与真机同源码。
18. 无人机领域的通信协议，PX4 的命令（解锁/切模式/返航）走它。
19. uXRCE-DDS 是面向嵌入式的轻量 DDS 方言；ROS2 用标准 DDS，两者需要转换。
20. 没有它，PX4 的 uXRCE-DDS 数据无法变成 ROS2 话题，节点看不到任何 `/fmu/` 消息。

## 附录 C：常用公式速查

这些公式在本课程各章都会用到。不需要背，但要知道**有这么一个关系**。

### 频率与周期

```text
周期(s) = 1 / 频率(Hz)
```

| 频率 | 周期 |
|---|---|
| 1 kHz | 1 ms |
| 250 Hz | 4 ms |
| 100 Hz | 10 ms |
| 20 Hz | 50 ms |

### 像素与角度（针孔相机）

```text
角度 θ ≈ atan(Δ像素 / 焦距f)
```

**小角度近似**：`θ ≈ Δ像素 / f`（弧度）。

例：`f=540`、`Δ=270` 像素 → `θ ≈ atan(0.5) ≈ 26.6°`。

### 像素与地面距离

相机在高度 `h` 时，图像上 `Δ` 像素对应地面距离：

```text
地面距离 d = h × Δ / f
```

例：`h=3m`、`Δ=100px`、`f=540` → `d = 3×100/540 ≈ 0.56m`。

**反过来**：想让地面精度达到 5cm，在 `h=0.6m` 时需要多少像素？

```text
Δ = d × f / h = 0.05 × 540 / 0.6 = 45 像素
```

（这正是第 6 章把末段容差收到 40 像素左右的依据。）

### 视场角

```text
FOV = 2 × atan(宽度一半 / f)
```

例：宽 1280、`f=540` → `FOV = 2 × atan(640/540) ≈ 99.7°`。

### 升力与转速

```text
升力 ∝ 转速²
```

**推论**：转速加倍，升力约 4 倍。所以油门曲线是"前松后紧"。

### 续航

```text
能量(Wh) = 电压(V) × 容量(Ah)
可用能量 = 能量 × 放电深度(约 0.8)
续航(h) = 可用能量 / 平均功率(W)
```

### 速度与距离

```text
反应距离 = 速度 × (检测延迟 + 决策延迟 + 制动时间)
```

例：1.2 m/s × (0.05 + 0.1 + 0.3) ≈ 0.54 m（第 9 章）。

### 坐标变换（ENU ↔ NED）

```text
ned_x = enu_y
ned_y = enu_x
ned_z = -enu_z
```

**这是轴交换 + z 取负，不是旋转**（第 15 章那个 58 米事故）。

### 四元数到倾角

```text
cos(倾角) = 2 × (w² + z²) − 1
```

**注意**：这里的 `w, z` 是四元数的第 1 个和第 4 个分量（ROS 顺序 `x,y,z,w` 里的 `w` 与 `z`）。

### 三个容易记混的单位换算

| 换算 | 关系 |
|---|---|
| 度 → 弧度 | × π/180 ≈ ×0.01745 |
| 弧度 → 度 | × 180/π ≈ ×57.3 |
| m/s → km/h | × 3.6 |

**最常用的一条**：`90° = 1.5708 rad`，`180° = 3.1416 rad`。

## 附录 D：十个常见问题速答

这些是初学者最常问、但正文里散落在各处的问题。

### 1. 学这门课需要什么基础？

**会基本的 Linux 命令和 Python 就行。** 不需要懂控制理论、不需要飞过真机、不需要会 C++。

**唯一的前置是耐心**——环境搭建那一步会花掉一两个小时。

### 2. 一定要有 GPU 吗？

**不一定要，但强烈建议。**

| 场景 | 无 GPU 可以吗 |
|---|---|
| 第 1–4、10–14 章 | ✅ 可以 |
| 第 5–6 章（YOLO/视觉） | ⚠️ 能跑但很慢（第 5 章实测 CPU 约 6 秒/帧） |
| 第 7–9 章（SLAM/规划） | ✅ 可以（但世界复杂时会卡） |

**没有 GPU 的话**：跳过第 5 章的实时检测，只做离线验证（存图后批量跑）。

### 3. 为什么一定要用 Ubuntu 22.04？

因为 **ROS2 Humble 官方支持 22.04**。换版本会遇到：

| 版本 | 问题 |
|---|---|
| 20.04 | 没有 Humble 的 apt 包 |
| 24.04 | Humble 不官方支持，依赖冲突 |

**非要换的话**：用 Docker（课程没提供镜像，但可行）。

### 4. 仿真能替代真机吗？

**不能，但能替代 90% 的调试工作。**

| 能 | 不能 |
|---|---|
| 验证控制逻辑 | 验证传感器噪声 |
| 验证坐标系 | 验证电机延迟 |
| 验证任务编排 | 验证结构强度 |
| 无限次试错 | 体验真实风险 |

第 15 章那张"四层差距"表就是答案。

### 5. 为什么飞机老往一个方向漂？

**三个最常见原因**：

| 原因 | 怎么查 |
|---|---|
| EKF 原点重置 | 看局部坐标是否突然跳变 |
| 坐标系搞错（NED/ENU） | 让飞机朝北飞 1 米，看 x 还是 y 变 |
| 目标点算错 | 打印目标与实测位置 |

**第 4 章那个"贴地爬行"就是第一类。**

### 6. 为什么我的节点收不到任何话题？

**九成是 QoS 或命名空间**：

```bash
ros2 topic list | grep fmu        # 有没有
ros2 topic info -v <话题>          # QoS 对不对
```

**QoS 不匹配是静默的**——不报错，就是收不到（第 2 章）。

### 7. `ros2 run` 找不到我的包？

```bash
echo $AMENT_PREFIX_PATH | tr ':' '\n' | grep ros2_ws
```

**没有输出 = 没 source**。有输出但在 `/opt/ros` 后面 = source 顺序反了。

**每个新终端都要重新 source**（第 1 章 2.9 节）。

### 8. 判分总是 FAIL，但我觉得飞得挺好？

**去读 `metrics` 的 `how`**（第 16 章）。

**最常见的不一致**：

| 你以为 | 判分实际 |
|---|---|
| "到目标附近了" | 距离 < 0.8m 才算 |
| "飞得很稳" | 中位偏差 < 0.2m |
| "落下来了" | 必须 disarmed |

**判分的标准写在配置里，不在你的感觉里。**

### 9. 学完能做什么？

**能做**：

- 独立搭一套 SITL 环境
- 写 Offboard 控制程序
- 接传感器、做检测、做视觉伺服
- 跑 SLAM 与避障
- 多机编队与集群
- 给自己写的代码做自动判分

**还不能做**（需要额外学习）：

- 调真机 PID（需要实机经验）
- 写飞控固件（需要 C++ 与实时系统知识）
- 做产品级可靠性设计

### 10. 接下来该学什么？

按兴趣选：

| 方向 | 下一步 |
|---|---|
| **控制** | 学 MPC、看 PX4 的 `mc_pos_control` 源码 |
| **感知** | 学多视图几何、跑 ORB-SLAM3 |
| **规划** | 学轨迹优化（MINCO/EGO-Planner 原版） |
| **系统** | 学实时系统、看 PX4 的 uORB 调度 |
| **实机** | 买一套小四旋翼，从系留测试开始 |

**建议顺序**：**先把手上的东西做深**（比如把第 14 章那个 bug 修好），再横向扩展。

**修一个真 bug 学到的东西，比读十篇论文多。**
