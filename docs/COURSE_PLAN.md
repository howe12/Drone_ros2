> 目标：17 章全部达到统一深度，可**系统性学习**，每章可独立跑通、可取证、可判分。
> 状态：执行中。进度见文末表格。

## 一、统一标准（每章必须满足）

| 维度 | 要求 |
|---|---|
| **篇幅** | **每章约 1000 行（900–1100）**；靠层次与证据撑起来，不靠重复和空话 |
| **结构** | 本章问题 → 学习目标 → 前置知识 → 本章地图 → 1 最小路径 → 2 原理 → 3 案例 → 4 进阶 → 你可能卡在这里 → 任务卡 → 检查清单 → 小结 |
| **原理** | 6–8 节，每节 50–80 行：概念 → 机制 → 本项目的实现位置 → 可观察证据 → 常见误解 |
| **案例** | 4–6 个，每个含背景 / 做法 / 结果（真实数据）/ 要点 |
| **任务卡** | 4–5 张，六段式；第 3 段"AI 提示"（先写后问）；**最后一张无 AI 区** |
| **代码** | 关键实现给出**带注释的代码片段**（来自仓库真实代码，不是伪代码） |
| **数据** | 参数表、话题表、判分指标表、实测性能数字 |
| **概念** | 术语首现即解释，或链接 [术语表](GLOSSARY.md)；新术语同步登记 |
| **图** | ≥3 张；优先级：官方图 > 实测截图 > 生图占位 |
| **图注** | 图片下方**单独一行加粗陈述句** |
| **验收** | 检查清单含"关掉 AI 能独立复现" |
| **诚实** | 未验证内容标 ⚠️，不得写成实测通过 |

### 1000 行的构成（蓝本）

| 部分 | 行数 | 内容 |
|---|---|---|
| 本章问题 + 学习目标 + 前置 + 本章地图 | 60–80 | 场景开场、目标表、先跑再懂、路线表 |
| 1 最小路径 | 150–200 | 分步命令 + 预期输出 + 截图 + 首个成功判据 |
| 2 原理（6–8 节） | 400–480 | 每节：概念解释、机制图/表、代码位置、证据、误解 |
| 3 案例（4–6 个） | 180–220 | 真实故障/调参/对比，含数据 |
| 4 进阶（可选） | 80–120 | 性能、扩展、与其他章的关系 |
| 你可能卡在这里 | 30–40 | 8–12 行症状表 |
| 任务卡（4–5 张） | 180–220 | 六段完整，含 AI 提示与验收 |
| 检查清单 + 小结 | 40 | 能力自检与下一步 |
| 附录：参数/话题速查 | 40–60 | 本章涉及的全部名字一表打尽 |

## 四、每章的作业流程（保证"做法没问题"）

1. **读源码与场景**：确认节点名、话题、参数、判分指标真实存在（不凭记忆写）。
2. **实跑验证**：至少跑通本章主命令，确认日志/话题/数值与文档一致。
3. **取证截图**：关键步骤截 Gazebo 画面、话题输出、判分报告，存入 `docs/images/`。
4. **改文档**：按统一标准重写；图注写陈述句；术语就地解释。
5. **回填实测**：把跑出来的真实数字写进正文（不是"应该"）。
6. **提交**：显式路径 `git add`，提交信息写清章节与改动；双推 GitHub/Gitee。
